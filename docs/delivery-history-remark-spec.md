# 交付中心历史记录备注展示规范

本文档只说明历史记录表格中 `备注` 字段的展示规则，供前后端开发联调用。

## 1. 目标

`备注` 字段只负责展示该条历史记录最关键的结果信息。

要求：

1. 文案简洁。
2. 同类动作使用固定句式。
3. 不重复项目名、操作名、操作人。
4. 不写冗余过程描述。

## 2. 适用动作

当前需要支持以下动作：

- 上传文件
- 提帧配置更新
- 审核通过
- 审核驳回
- 全部通过

不展示：

- 修改建议提交

## 3. 展示规则总表

| 操作 | 备注展示格式 | 示例 |
| --- | --- | --- |
| 上传文件 | `上传了 X 个文件` | `上传了 21 个文件` |
| 提帧配置更新 | `{比例} / {帧率} fps` | `1920（宽屏） / 30 fps` |
| 审核通过 | `{结果摘要}` | `第 24 集通过` |
| 审核驳回 | `驳回说明：{驳回原因}` | `驳回说明：缺少字幕文件` |
| 全部通过 | `{结果摘要}` | `1-24 集通过` |

## 4. 各动作详细规则

### 4.1 上传文件

展示格式：

```text
上传了 {fileCount} 个文件
```

字段要求：

- `fileCount` 必须是数字
- 小于 0 时按 `0` 处理
- 为空时按 `0` 处理

示例：

```text
上传了 4 个文件
上传了 21 个文件
上传了 0 个文件
```

禁止输出：

```text
项目A上传了完整成片
已提交审核
补传成功，等待审核
```

原因：

- 项目名、操作类型已经在其他列展示
- `备注` 不再重复这些信息

### 4.2 提帧配置更新

展示格式：

```text
{ratio} / {fps} fps
```

字段要求：

- `ratio` 直接使用当前配置值
- `fps` 直接使用当前配置值
- 不增加“比例”“帧率”等前缀

示例：

```text
1920（宽屏） / 30 fps
1080（竖屏） / 60 fps
1080（方屏） / 24 fps
```

禁止输出：

```text
比例 1920（宽屏），帧率 30
提帧配置已更新
当前修改为 1080（竖屏）
```

### 4.3 审核驳回

展示格式：

```text
驳回说明：{reason}
```

字段要求：

- `reason` 必须来自真实驳回说明
- 如果原始值已经带 `驳回说明：` 前缀，不重复拼接
- 如果为空，兜底显示：

```text
驳回说明：无
```

示例：

```text
驳回说明：缺少字幕文件
驳回说明：音频电平异常
驳回说明：封面人物边缘需修正
```

禁止输出：

```text
已驳回
审核未通过
需要重新修改后再提交
```

原因：

- 这类文案缺少真正可执行的驳回原因

### 4.4 审核通过

展示格式：

```text
{resultText}
```

字段要求：

- 直接展示通过结果
- 不重复“审核通过”四个字
- 文案优先短句

示例：

```text
第 24 集通过
分集图片通过
成片通过
```

禁止输出：

```text
审核通过
第 24 集审核通过
该素材已审核通过
```

推荐：

- 如果有明确集数，用集数结果
- 如果没有集数，用类型结果

### 4.5 全部通过

展示格式：

```text
{rangeText}通过
```

示例：

```text
1-24 集通过
1-3 集通过
全部通过
```

说明：

- 有范围时优先展示范围
- 无范围时可直接显示 `全部通过`

## 5. 前端处理建议

建议前端统一封装 `formatHistoryRemark(record)`：

```js
function formatHistoryRemark(record) {
  if (!record) return '--';

  if (record.action === '审核驳回') {
    if (!record.remark) return '驳回说明：无';
    return record.remark.startsWith('驳回说明：')
      ? record.remark
      : `驳回说明：${record.remark}`;
  }

  if (record.action === '上传文件') {
    return record.remark || '上传了 0 个文件';
  }

  return record.remark || '--';
}
```

## 6. 后端返回建议

为了减少前端判断，建议后端尽量直接返回符合规范的 `remark` 值。

推荐返回：

```json
{
  "action": "上传文件",
  "type": "成片",
  "remark": "上传了 21 个文件"
}
```

```json
{
  "action": "审核驳回",
  "type": "字幕",
  "remark": "缺少字幕文件"
}
```

```json
{
  "action": "提帧配置更新",
  "type": "提帧配置",
  "remark": "1920（宽屏） / 30 fps"
}
```

## 7. 联调验收清单

开发完成后，至少检查以下内容：

1. 上传类是否统一显示为 `上传了 X 个文件`
2. 驳回类是否统一显示为 `驳回说明：...`
3. 提帧配置是否统一显示为 `{比例} / {帧率} fps`
4. 通过类是否没有重复“审核通过”字样
5. 空值是否有兜底
6. 修改建议提交是否没有进入历史记录展示
